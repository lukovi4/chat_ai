# Chat Widgets — спецификация

> Детальный уровень для ТЗ (не ADR: здесь «что и как», решения-«почему» — в
> `docs/adr/`). Доменные термины и границы — в `CONTEXT.md` §Chat Widgets.

## Состав

Ровно три части, композитного экрана нет — экран собирает приложение:

1. **Message List** — список сообщений активной Conversation; подписан на
   `session.states` и `session.tokens`, читает `session.snapshot`. Владеет
   плейсхолдером «думает», строкой ошибки, действиями resend/regenerate и
   empty-reply action.
2. **Message Bubble** — ровно одно сообщение (любой роли, видимые Content
   Parts и статусные маркеры) плюс Copy; используется списком, экспортируется
   отдельно. Standalone-границы: не владеет `ChatSession`, не показывает
   строку ошибки, «думает», resend/regenerate и empty-reply action; `complete`
   ответ бота без видимого содержимого сам не рисует bubble; system Message —
   plain text в визуальном стиле ассистента. Внешним выравниванием не владеет,
   сам себя в `Align`/позиционирующий `Row` не оборачивает: при standalone-
   использовании его располагает родитель приложения.
3. **Input Bar** — поле ввода и отправка; владеет draft и превью изображений.
   Публичных controller/focus/keyboard/scroll API в v1 нет.

## Кастомизация

Три уровня, граница зафиксирована в CONTEXT.md:

- **Chat Theme** (вид — полный контроль приложения): plain immutable const
  value class, все поля nullable, null = дефолт из `Theme` приложения. Цвета
  (фон, бабл юзера/бота, иконки, ошибка, заливка инпута), отступы
  (`messageListPadding`, `bubblePadding`, `inputBarPadding`,
  `messageSpacing`), `TextStyle` каждого вида текста (юзер, бот, время,
  ошибка, ввод, плейсхолдер инпута; цвет текста задаёт сам `TextStyle` —
  отдельных полей цвета текста нет), формы (`ShapeBorder` бабла юзера/бота;
  хвостик = свой `ShapeBorder`, отдельного tail-поля нет), `maxBubbleWidthFactor`,
  `imageThumbnailSize`. Отдельных animation/icon/controller/scroll-полей нет.
  `ChatTheme` применяется и к Input Bar. Точный список полей, дефолты и
  ограничения закреплены в V1_SPEC.md §7: нарушение бросает `ArgumentError`
  при build до рендера/вызова callback, одинаково в debug и release; это не
  debug-only `assert` и не silent clamp.
- **Переключатели компоновки** (готовые варианты, закрытый список):
  выравнивание своих баблов справа/слева (`ownMessagesRight`), аватары
  показать/скрыть и сторона (`showAvatars` + `avatarSide`
  leading/trailing), позиция времени (`timestamps`: none / belowBubble).
  Всем внешним выравниванием владеет Message List: assistant/system всегда
  слева; user справа при `ownMessagesRight: true`, иначе слева.
- **Builder-слоты** (замена части): свой аватар, свой вид ошибки, свой
  индикатор «думает», свой рендер части сообщения. Произвольная перестановка
  элементов — не параметр: пересборка экрана из частей.

## Отображение состояний

| Состояние | Отображение |
|---|---|
| `Sending` («думает») | бабл-плейсхолдер бота с пульсирующим `···` |
| `AwaitingTool` | **тот же** `···` — от «думает» не отличается (упрощение v1) |
| `Streaming` | плейсхолдер растёт текстом из Token Stream |
| `Done` | обычное сообщение |
| `Failed` | частичный текст (если был) остаётся + строка ошибки под ним; текст ошибки даёт приложение (см. «Ошибки и строки») |
| юзер `sending` | бабл приглушён / индикатор отправки |
| юзер `failed` | иконка ошибки у бабла |
| ассистент `interrupted` | частичный текст остаётся + маркер «прервано» |

**Tool-части не рендерятся.** `ToolCallPart`/`ToolResultPart` внутри
assistant-сообщения по умолчанию невидимы — это машинный обмен, не текст
бота; рисуются только text/image-части. Приложение может показать их через
`partBuilder` (например, «🔍 ищу в заметках…»).

**Цепочка `partBuilder`:** `TextPart`/`ImagePart`/`ToolCallPart`/
`ToolResultPart` сначала передаются в `partBuilder`; вернул `null` —
используется default rendering (для tool-частей default = скрыто).

`ProviderOpaquePart` невидим всегда: он не рендерится и **никогда не передаётся
в `partBuilder`**. Это техническая provider-continuity запись, не продуктовый
контент.

**Пустой ответ** (`Done` без текста; Core: валидный Done, не ошибка) —
пустой бабл не рисуется; на его месте **компактная иконка-кнопка
regenerate** без текста (паттерн Record_transcribe «состояние без текста»;
«платно = явный тап» соблюдено). Опциональный `emptyReplyBuilder` — приложение
рисует своё. Сообщение остаётся в истории/сериализации.

## Действия — простая модель

**Встроено** (замыкается на механизмы Core, ноль кода приложения):

| Действие | Где | Механизм Core |
|---|---|---|
| Stop | Input Bar: кнопка отправки превращается в «стоп» в `Sending`/`AwaitingTool`/`Streaming` — во всех фазах, где Core обещает cancel | `cancel` |
| Resend | кнопка у `failed` сообщения юзера — **только когда оно последнее в Conversation** (у более старого `failed` кнопки нет: там resend — no-op Core) | resend (безопасная сторона Retry Boundary) |
| Regenerate | кнопка у `interrupted` ответа бота и у empty-reply action | regenerate («платно = явный тап») |
| Строка-ошибка | одно действие = recovery-target текущего `Failed`, который Core вычисляет по тому, что реально сделал сбойный reply (resend только когда anchor стал `failed`; regenerate только когда assistant стал `interrupted`; `none` — pre-Message-отказ или иной Failed без восстановления), и отдаёт виджету непубличным мостом — **не выводится из истории** | resend / regenerate / нет |
| Copy | long-press на сообщении: все видимые TextPart по порядку через `"\n"`, исходный текст (markdown source как есть); image/tool/opaque части не копируются; видимого текста нет — no-op | буфер обмена |

**Не встроено в v1:** edit сообщения юзера (механизм truncate-and-resend в
Core остаётся, UI приложение собирает само при желании); regenerate у
успешного (`complete`) ответа — виджеты не рисуют, механизм доступен
приложению.

## Ошибки и строки

Принцип Record_transcribe («codes out, strings never») сохранён дословно:
в пакете ни одной user-facing строки, `developerDetail` — только для логов.
Адаптация для разговорной поверхности:

- **Message List: обязательный параметр `failureText`** — функция
  `причина → строка`. Единственный обязательный параметр во всех трёх
  виджетах помимо данных (`session` у Message List и Input Bar, `message` у
  Bubble); приложение пишет один switch на 10 кодов каталога
  (CONTEXT.md §Failure).
- **При `Failed`** виджет рисует одну строку-ошибку в ленте на месте обрыва:
  иконка + текст из `failureText` + кнопка действия — recovery-target
  текущего `Failed` из Core (resend сбойного anchor / regenerate прерванного
  ответа), либо **без кнопки**, когда валидного восстановления нет
  (pre-Message-отказ). Не снекбар, не баннер, не диалог.
- **Опциональный `errorBuilder`** — приложение рисует место ошибки целиком
  само; `failureText` тогда не используется. `retry` **nullable**: `null`
  означает «валидного восстановления нет» — приложение не показывает retry;
  no-op callback пакет не передаёт.
- **Input Bar: опциональный `hint`** (плейсхолдер поля) — не передан → поле
  пустое. Дефолтных текстов нет.

Границы: виджет не содержит логики повторов (счётчики, backoff, «когда
ретраить» — только Core; кнопка = один вызов Core), не показывает
`developerDetail`, не валидирует результат резолвера, без severity/тостов/
автоскрытия.

## Markdown

- **Ответы бота: markdown по умолчанию.** Один рендерер-dependency,
  устойчивый к незакрытой разметке на растущем (стриминговом) тексте;
  выбор пакета — на этапе ТЗ. Флаг отключения — `markdown` (default `true`)
  ровно у двух виджетов: `ChatMessageList` и `MessageBubble`; `false` →
  plain text. Применяется только к assistant `TextPart`.
- **Код-блоки:** моноширинный + фон (даёт рендерер). Отдельной кнопки
  «копировать код-блок» в v1 нет — есть copy всего сообщения.
- **Сообщения юзера: всегда plain text** — случайные `*` не превращаются
  в разметку.
- Свой рендер — через builder-слот (см. «Кастомизация»), собственной логики разметки
  пакет не содержит.

## Время и скролл

- `TimestampPosition.none` (default) ничего не показывает; `belowBubble`
  показывает `createdAt` сообщения в локальном времени, формат — из
  Flutter/Material locale.
- Список остаётся приклеенным к низу при новых сообщениях/токенах, **только
  если пользователь уже был внизу**; прокрутившего историю вверх streaming
  вниз не возвращает.
- Публичного ScrollController/scroll-policy API в v1 нет.

## Фото — паттерн «кнопка в пакете, пикер у приложения»

- **Input Bar: кнопка прикрепления** видна только если передан колбэк
  `onAttach`; приложение открывает свой пикер (плагины, пермишены — его)
  и возвращает картинку. Нет колбэка — нет кнопки.
- **Превью до отправки:** миниатюра над полем с крестиком удаления.
  Отправка → image Content Part. Лимит: `maxAttachments` null → берётся
  `session.imageOptions.maxImagesPerMessage` (дефолт 4); non-null должен быть
  `> 0` (иначе тот же release-safe `ArgumentError` при build) и может только
  понизить его — effective cap = `min(maxAttachments, лимит сессии)`. Повторные прикрепления добавляют
  изображения до cap; если колбэк вернул больше оставшихся мест — принимаются
  первые в исходном порядке до cap; `[]` = отмена пикера, ничего не меняется.
  Core повторно проверяет лимит; ресайз (2048 px, JPEG) делает Core — см.
  CONTEXT.md §Image Attachment.
- **Bubble:** image-часть — ограниченная миниатюра (размеры из Chat Theme).
  Полноэкранный просмотр не в пакете: опциональный `onImageTap`, без него
  тап ничего не делает.
- Лимиты и ресайз решены: CONTEXT.md §Image Attachment (configurable default 4,
  default 2048 px JPEG, картинка без текста валидна).

**Draft принадлежит Input Bar.** Публичные controller/scroll/keyboard policy в
v1 не добавляются. `onAttach` и `onMic` всегда await-ятся; exception сохраняет
draft и передаётся в `FlutterError`, не создавая chat Failure. После send draft
очищается только по внутреннему Core-result `accepted`; `noOp` и `rejected`
(busy, invalid image/count, preprocessing/checkpoint failure) сохраняют текст и
превью.

## Mic-кнопка — в v1

Тот же паттерн, что фото: опциональный колбэк `onMic` — есть колбэк → есть
кнопка. Приложение само записывает и транскрибирует (клей с
`record_transcribe` — в приложении; chat_ai не зависит от аудио-пакетов,
CONTEXT.md §Voice Input) и возвращает `String?`; `null` ничего не меняет,
непустой результат Input Bar **вставляет в текущую selection** (заменяя
выделение, курсор после вставки) — не отправляет автоматически.

## Иконки по умолчанию (Material, без строк)

send `Icons.send` · stop `Icons.stop` · attach `Icons.attach_file` · mic
`Icons.mic` · удаление превью `Icons.close` · resend / regenerate /
empty-reply regenerate `Icons.refresh` · ошибка `Icons.error_outline` ·
прервано `Icons.stop_circle_outlined` · дефолтный аватар `Icons.person`.
Tooltip'ов и других собственных user-facing строк в пакете нет; текст ошибки
всегда приходит через `failureText` (или приложение заменяет строку целиком
через `errorBuilder`).
