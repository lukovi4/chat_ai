# Chat Widgets — спецификация

> Детальный уровень для ТЗ (не ADR: здесь «что и как», решения-«почему» — в
> `docs/adr/`). Доменные термины и границы — в `CONTEXT.md` §Chat Widgets.

## Состав

Ровно три части, композитного экрана нет — экран собирает приложение:

1. **Message List** — список сообщений активной Conversation; подписан на
   Conversation State (фазы) и Token Stream (растущий ответ).
2. **Message Bubble** — одно сообщение (любой роли, все Content Parts);
   используется списком, экспортируется отдельно.
3. **Input Bar** — поле ввода и отправка.

## Кастомизация

Три уровня, граница зафиксирована в CONTEXT.md:

- **Chat Theme** (вид — полный контроль приложения): цвета (бабл юзера/бота,
  фон, текст, иконки), отступы (паддинги баблов, промежутки, отступы экрана),
  `TextStyle` каждого вида текста (сообщение, время, ошибка, плейсхолдер
  инпута), формы (скругления, max-ширина бабла, хвостик). Дефолты — из `Theme`
  приложения.
- **Переключатели компоновки** (готовые варианты): выравнивание баблов (свои
  справа / все слева), аватары показать/скрыть и сторона, позиция времени.
- **Builder-слоты** (замена части): свой аватар, свой вид ошибки, свой
  индикатор «думает», свой рендер части сообщения. Произвольная перестановка
  элементов — не параметр: пересборка экрана из частей.

## Отображение состояний

| Состояние | Отображение |
|---|---|
| `Sending` («думает») | бабл-плейсхолдер бота с пульсирующим `···` |
| `AwaitingTool` | **тот же** `···` — от «думает» не отличается (упрощение v1) |
| `Streaming` | плейсхолдер растёт текстом из Token Stream |
| `Done` | обычное сообщение |
| `Failed` | частичный текст (если был) остаётся + строка ошибки под ним; текст ошибки даёт приложение (см. «Ошибки и строки») |
| юзер `sending` | бабл приглушён / индикатор отправки |
| юзер `failed` | иконка ошибки у бабла |
| ассистент `interrupted` | частичный текст остаётся + маркер «прервано» |

**Tool-части не рендерятся.** `ToolCallPart`/`ToolResultPart` внутри
assistant-сообщения по умолчанию невидимы — это машинный обмен, не текст
бота; рисуются только text/image-части. Приложение может показать их через
`partBuilder` (например, «🔍 ищу в заметках…»).

`ProviderOpaquePart` невидим всегда: он не рендерится и **никогда не передаётся
в `partBuilder`**. Это техническая provider-continuity запись, не продуктовый
контент.

**Пустой ответ** (`Done` без текста; Core: валидный Done, не ошибка) —
пустой бабл не рисуется; на его месте **компактная иконка-кнопка
regenerate** без текста (паттерн Record_transcribe «состояние без текста»;
«платно = явный тап» соблюдено). Опциональный `emptyReplyBuilder` — приложение
рисует своё. Сообщение остаётся в истории/сериализации.

## Действия — простая модель

**Встроено** (замыкается на механизмы Core, ноль кода приложения):

| Действие | Где | Механизм Core |
|---|---|---|
| Stop | Input Bar: кнопка отправки превращается в «стоп» в `Sending`/`AwaitingTool`/`Streaming` — во всех фазах, где Core обещает cancel | `cancel` |
| Resend | кнопка у `failed` сообщения юзера | resend (безопасная сторона Retry Boundary) |
| Regenerate | кнопка у `interrupted` ответа бота; строка-ошибка без assistant вызывает regenerate только когда последний user Message `sent` | regenerate («платно = явный тап») |
| Copy | long-press на сообщении | буфер обмена |

**Не встроено в v1:** edit сообщения юзера (механизм truncate-and-resend в
Core остаётся, UI приложение собирает само при желании); regenerate у
успешного (`complete`) ответа — виджеты не рисуют, механизм доступен
приложению.

## Ошибки и строки

Принцип Record_transcribe («codes out, strings never») сохранён дословно:
в пакете ни одной user-facing строки, `developerDetail` — только для логов.
Адаптация для разговорной поверхности:

- **Message List: обязательный параметр `failureText`** — функция
  `причина → строка`. Единственный обязательный параметр во всех трёх
  виджетах; приложение пишет один switch на 10 кодов каталога
  (CONTEXT.md §Failure).
- **При `Failed`** виджет рисует одну строку-ошибку в ленте на месте обрыва:
  иконка + текст из `failureText` + кнопка действия из раздела «Действия»
  (resend — последний user Message `failed`; regenerate — ответ бота
  `interrupted` или последний user Message `sent` без assistant).
  Не снекбар, не баннер, не диалог. Один механизм на оба случая ошибки.
- **Опциональный `errorBuilder`** — приложение рисует место ошибки целиком
  само; `failureText` тогда не используется.
- **Input Bar: опциональный `hint`** (плейсхолдер поля) — не передан → поле
  пустое. Дефолтных текстов нет.

Границы: виджет не содержит логики повторов (счётчики, backoff, «когда
ретраить» — только Core; кнопка = один вызов Core), не показывает
`developerDetail`, не валидирует результат резолвера, без severity/тостов/
автоскрытия.

## Markdown

- **Ответы бота: markdown по умолчанию.** Один рендерер-dependency,
  устойчивый к незакрытой разметке на растущем (стриминговом) тексте;
  выбор пакета — на этапе ТЗ. Флаг для отключения (plain text).
- **Код-блоки:** моноширинный + фон (даёт рендерер). Отдельной кнопки
  «копировать код-блок» в v1 нет — есть copy всего сообщения.
- **Сообщения юзера: всегда plain text** — случайные `*` не превращаются
  в разметку.
- Свой рендер — через builder-слот (см. «Кастомизация»), собственной логики разметки
  пакет не содержит.

## Фото — паттерн «кнопка в пакете, пикер у приложения»

- **Input Bar: кнопка прикрепления** видна только если передан колбэк
  `onAttach`; приложение открывает свой пикер (плагины, пермишены — его)
  и возвращает картинку. Нет колбэка — нет кнопки.
- **Превью до отправки:** миниатюра над полем с крестиком удаления.
  Отправка → image Content Part. Лимит берётся из
  `session.imageOptions.maxImagesPerMessage` (дефолт 4); локальный параметр
  Input Bar может только понизить его. Core повторно проверяет лимит;
  ресайз (2048 px, JPEG) делает Core — см. CONTEXT.md §Image Attachment.
- **Bubble:** image-часть — ограниченная миниатюра (размеры из Chat Theme).
  Полноэкранный просмотр не в пакете: опциональный `onImageTap`, без него
  тап ничего не делает.
- Лимиты и ресайз решены: CONTEXT.md §Image Attachment (configurable default 4,
  default 2048 px JPEG, картинка без текста валидна).

**Draft принадлежит Input Bar.** Публичные controller/scroll/keyboard policy в
v1 не добавляются. `onAttach` и `onMic` всегда await-ятся; exception сохраняет
draft и передаётся в `FlutterError`, не создавая chat Failure. После send draft
очищается только по внутреннему Core-result `accepted`; `noOp` и `rejected`
(busy, invalid image/count, preprocessing/checkpoint failure) сохраняют текст и
превью.

## Mic-кнопка — в v1

Тот же паттерн, что фото: опциональный колбэк `onMic` — есть колбэк → есть
кнопка. Приложение само записывает и транскрибирует (клей с
`record_transcribe` — в приложении; chat_ai не зависит от аудио-пакетов,
CONTEXT.md §Voice Input) и возвращает `String`; Input Bar **вставляет текст в
поле** — не отправляет автоматически.
